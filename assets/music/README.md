# 背景音乐

| 文件 | 在哪儿放 | 来源 | 时长 |
| --- | --- | --- | --- |
| `start.ogg` | 选人 / 备战界面，循环 | Suno 生成（2026-09-21，付费档） | 90.5s |
| `battle.ogg` | 进图之后，循环 | Suno 生成（2026-09-21，付费档） | 119.9s |

**来源就是这一行，别再写成“从 doc/ 的视频里抽的”。** 上一版那两首是订阅制素材站的曲子，
而那类授权按用途划分，覆盖不了“做进一个公开发行的游戏里”，第三方录你的游戏发视频还会吃
Content ID 声明。这两首是自己生成的，付费档在生成当时就已订阅 —— 商用权归自己且永久有效，
和订阅状态脱钩。原始 mp3 和生成记录（账号、日期、提示词）留在本地，`doc/` 不进仓库。

转法：

```
ffmpeg -i doc/start.mp3 -vn -ac 2 -ar 44100 \
       -af "loudnorm=I=-18:TP=-2:LRA=11" -c:a libvorbis -q:a 4 assets/music/start.ogg
```

`-vn` 是必要的：Suno 的 mp3 带一张封面图，不丢掉它会被当成一路视频流编进去。

`loudnorm` 是为了**两首对齐**，不是为了响：换曲的时候如果一首明显比另一首大声，
玩家听到的不是"换了首曲子"而是"音量突然变了"。这两首实测 -17.2 / -17.0 LUFS，差 0.2 LU；
真峰 -1.7 / -3.2 dBFS，都没顶到头。和上一版那两首（-17.0 / -17.3）也在同一档上，所以换掉
素材不会让整个游戏的音乐忽然变响或变轻。

## 几条和音效不一样的规矩

**循环用 AudioBufferSourceNode 的 `loop`，不用 `<audio loop>`。** 后者每一圈接缝处有一个
听得见的空档（浏览器要重新起播）。代价是整首要解码进内存，而且**两首都常驻**（`load()`
一次把 TRACK_URLS 里的全解出来）：现在 90.5s + 119.9s，44.1kHz 立体声 float32 算下来
约 74MB。上一版是 124 秒共约 44MB —— 换素材多吃了三十兆。要压下来就把曲子裁短，
选人界面那首尤其不需要九十秒。

**循环区间是算出来的，不是整条缓冲**（`music.ts` 的 `voiced()` + `loopStart`/`loopEnd`）。
两首素材首尾都带着可观的静音：

| | 头部空 | 尾部空 | 每圈断档 | 实际循环段 |
| --- | --- | --- | --- | --- |
| `start.ogg` | 0.54s | 0.02s | **0.56s** | 89.90s |
| `battle.ogg` | 0.73s | 1.84s | **2.57s** | 117.28s |

（上一版那两首首尾空得多，每圈断三秒以上。这一版的素材干净不少，但这套机制照样要留着 ——
下次换曲子的人不会知道自己那首首尾有多少静音。）

照原样循环，每转一圈就断掉上面那一段，听起来不像"循环的背景乐"，像"放完了又重放"。更要命
的是**第一次起播**：点下去要愣一下才出声，然后以满音量突然出现 —— 那个从无到有的落差会
被听成"音乐好大"，而且只在第一次出现（之后音乐已经在中段连续播着，没有对比）。

所以起播点和循环起点都取第一个听得见的采样，循环终点取最后一个。判据和音效那边同源
（`bank.ts` 的 `ONSET_FRACTION`）：相对本首峰值 -34dB。不改文件 —— 原始 mp3 还在，但裁
静音这件事交给运行时做，换一首曲子进来就不用记得再裁一遍。

**加载不挂在加载条上。** 解码那几百毫秒摆进启动流程，就是让玩家为一首还没开始听的曲子
干等。后台解，解好之前选人界面是安静的，解好了 `main.updateMusic` 自己接上。

**刚打开页面时音乐不会响，要等第一次点击 —— 这不是 bug，是浏览器的硬规矩。**
自动播放策略要求 AudioContext 必须在一次真实用户手势里 resume，页面自己是叫不醒它的。
实测（不加 `--autoplay-policy` 覆盖的 Edge）：

```
还没碰过任何东西: ctx=suspended, track=null, pending="start"   ← 想放什么已经记下了
点了一下之后    : ctx=running,   track="start"
```

`setTrack` 把想放的那一首记在 `wanted` 上，而 `updateMusic` 每帧推一次，所以**第一次点击
落地的同一瞬间音乐就接上**，不用等下一次场景切换。`mixer.unlock` 里还会不等手势先自己
试一次 `resume()`：Chrome/Edge 的策略会看站点的 Media Engagement Index，常来的玩家那一
次会成功，一进来就有音乐。新玩家仍旧等第一次点击。

真要做到"一进来就有声"，唯一的办法是加一道"点击开始"的门 —— 那是产品决定，不是技术问题。

**音乐总线比音效低一大截**（`mixer.ts` 的 `MUSIC_GAIN = 0.38`）。音乐是一直在响的底子，
音效是偶尔冒出来的信息；一样响的话，砍中那一下就得跟鼓点抢位置。

**两首各自还有一个音量**（`music.ts` 的 `TRACK_VOLUME`）：选人 0.15，战斗 1（差 16dB）。
选人那一首是真正意义上的背景音 —— 玩家在那一屏读属性、比技能、挑地图，音乐只负责让这屏
不至于死寂，不该参与表达；战斗那首相反，它是这一局的情绪底子，该有存在感。素材本身已经
用 loudnorm 对齐过，所以这个比例是纯粹的设计意图，不是在补素材的响度差。

**选人那首不做任何淡入淡出**（`TRACK_FADE.start = 0`）。它本来就压得极低，一首几乎听不见
的背景音再慢慢爬上来，唯一的效果是让人分不清"现在到底是什么音量"—— 尤其它起播的时刻取决
于玩家什么时候点第一下（自动播放策略见上），于是同一屏每次进来听感都不一样。定死一个音量，
从第一个采样起就是它，听感才是稳的。

战斗那首保留 1 秒交叉：它有存在感，而且进图那一下是从选人曲换过来的，两首之间硬切才真突兀。
离开选人界面时那一首是硬停的，波形中间断开会有一个台阶 —— 可以接受，它的幅度只有 0.057，
而那一刻黑幕正在落、换屏声正在响，这点台阶完全盖住了。

## 弹出框来了要让开 —— 只有战斗那一侧

三选一、暂停、结算盖上来时，音乐压到三成（`MUSIC_DUCK`），0.25 秒渐变过去。
不是静音：那几秒玩家在读字、在做选择，音乐顶在前面会烦；但完全掐掉又显得死寂，像是卡住了。

**商店和战绩不在这张单子上**，虽然它们也是盖上来的整屏面板。因为选人那一首本来就压得很低
（`TRACK_VOLUME.start`），已经是"不参与表达"的背景音，再压一档既听不出来，又会让人在那
一屏上听见音量来回浮动，反而显得不稳。选人界面音乐从头到尾一个音量。

判断写在 `main.updateMusic` 里，**每帧重算一次**，不是在各个切换点各写一句。
换屏声那种是*事件*（漏一处就少响一声），而"现在该放哪一首、要不要让开"是*状态* ——
状态挂在切换点上，只要有一条路忘了写，音乐就会一直停在错的档位，而且是静悄悄地错。

## 开关

设置里音效和音乐分成两行，各关各的：想留着打击声只关音乐的人，不该被迫连音效一起关掉。
两条都存进档（`ProfileSettings`），旧存档靠 `freshSettings()` 的合并自动补上默认值。
关掉只是把总线推到 0，曲子还在后台走 —— 再打开就接着响，不会从头开始。

# 游戏音效素材目录

每个文件夹代表一个逻辑音效。文件名随意，可以放多个变体；游戏每次播放时会随机选择一个。
支持小写扩展名 `.ogg`、`.wav`、`.mp3`，加入或替换文件后重新构建即可生效。

## 投放位置

| 文件夹 | 用途 | 现有素材 |
| --- | --- | --- |
| `attack_swing/` | 自动攻击每次起手 | 11 条，218–718ms，峰值 -7dBFS |
| `battle_hit/` | 攻击命中敌人 | 13 条，305–719ms，峰值 -1dBFS |
| `footstep/` | 玩家疾走时每次落脚 | 14 条，99–152ms，峰值 -14dBFS |
| `scene_switch/` | 整屏切换 | 1 条，734ms，峰值 -5dBFS |
| `card_deal/` | 三选一弹出、选完飞出去 | 1 条，1765ms，峰值 -5dBFS |

`hud_click.ogg` 是界面按钮声，来自 Kenney.nl（CC0），单独一件不进文件夹。

三档响度是按**每秒响几次**定的，不是按"哪个重要"：命中 -1dB，挥击比它低 6dB，脚步再低
7dB。挥击每一刀都响、脚步一秒响四到八次，跟命中一样响的话，一是挥空和砍中分不出来，
二是整局被自己的脚盖住。

## 脚步为什么能和腿对上

触发点不是"脚离地面够近"，而是**步态相位的跨越**：相位跨过 0 是左脚落地、跨过 0.5 是
右脚。动画器里相位的前半程恰好是支撑段（`stepTarget` 里 `z = 0` 的那一半），所以这两个
跨越就是落脚那一帧。量过：触发瞬间那只脚离地 0.000、且还在身前（y 为正），正是刚踩实
还没往身后滑的那一帧。

素材长度是被步频卡住的：走路 4.47 步/秒（间隔 224ms），疾走 8.00 步/秒（间隔 **125ms**）。
所以脚步最长裁到 130ms，`bank.ts` 里那道 gap 也必须小于 125ms（现在是 50ms），
否则正常的步子会被自己的闸挡掉。

**只有疾走才响**（main.ts 的 flushSoundEvents 按 `battle.sprinting` 过一道）。割草游戏里
玩家几乎一直在移动，走路也报的话这个声音就成了整局不停的背景噪音 —— 一直在响的东西等于
没在说话。只在疾走时响，它才有话说：那是"我正在冲"，而冲刺恰恰是玩家主动按下去的动作。

文件名不参与任何逻辑，播放时在文件夹里随机挑一条（见 `src/audio/bank.ts`）。编号只是为了
人看着顺眼，删掉几条或者加进去几条都不用改代码。

换屏和卡牌各只有一条，而且 `jitter` 都是 0 —— 和界面点击声同一个理由：界面的声音要
"一模一样"，每次不同会让人觉得界面不稳、像是坏了。战斗音效才需要抖。

**换屏和卡牌是两个音效，不是一个。** 三选一是盖在战场上的一层，世界还在那儿（只是停了），
和"整屏换掉"不是一回事：那边是一道风，这边是一叠牌甩开。

卡牌那一条**弹出和选完各响一次，用的是同一条**：一叠牌甩开和收回本来就是同一个动静，
收场再配个新音色，听起来会像是又发生了一件别的事。两次之间隔的是玩家的反应时间（实测
按牌约 400ms），所以 `card-deal` 的 gap 只能给到 0.12 秒 —— 给大了收场那一声会被闸掉，
而且是悄悄吃掉，听起来就成了"有时候响有时候不响"。

## 为什么只有两个

上一版摆了七个语义（脚步、暴击、拾取、升级、首领出场）。撤掉的那五个都有同一个毛病：
画面上本来就各有自己的说法 —— 暴击是金色的大数字，拾取是飞向玩家的那一串，升级是弹出来的
卡牌，首领是屏幕上那条血条 —— 再配一个音效只是在割草的噪音里多抢一个声部。

留下来的两个是唯一**没有画面替身**的反馈：挥空的时候画面上什么都没有，而砍中的那一下手感
全在声音里。真需要别的语义了再一个一个加回来，加的时候至少知道它是为了解决什么。

## 这些是从哪来的

全部从 `doc/` 下的录屏里裁出来的（doc/ 不进仓库）。一段录音里常有好几下，中间隔着静音，
所以流程是**先切段、再去重、再裁**：

1. `silencedetect` 按静音把录音切成候选段。
2. 长段再查一遍段内起音 —— 有些是连着抡了两下，静音门限切不开（中间没到静音），
   但能量包络上是两个峰。这种拆开，隔得太近（<250ms）的不拆。
3. **两两做互相关去重。** 一条录音里连响十几下，听着像十几个变体，实际常常是同一条素材
   在循环。对齐后归一化再比，相关系数 > 0.9 就归成一类，每类只留一条。
   `hit3` 的 16 段就这样压成了 10 条；早先的 `swing.mp4` 那两下更是 0.9997，同一条。
4. 每条收紧到"相对本条峰值 -40dB"的实际有声部分，头留 3ms、尾留 15ms 给淡出，
   再按目标电平归一化，编成 ogg：

```
ffmpeg -ss <起点> -t <时长> -i doc/hit3.mp4 -vn \
       -af "afade=t=out:st=<尾部>:d=0.015,volume=<归一化增益>dB" \
       -ac 1 -ar 44100 -c:a libvorbis -q:a 5 battle_hit/hit02.ogg
```

末尾那 15ms 淡出不是讲究：波形停在非零值上，播放时会"啪"一声，比音效本身还响。
用 ogg 不用 wav 是因为体积差五倍 —— 24 条 wav 要一兆多，ogg 只要 228KB。

## 统一要求

- 都是一次性播放的 one-shot，不要无缝循环素材。
- **开头不用自己裁。** 加载器每次都会重新找起播点：按 3ms 能量包络，爬到峰值 -12dB
  才算"响了"，前面那一段一律跳过 —— 不只是静音，连素材自带的几十毫秒"抡起来"也跳。
  这条线在 `src/audio/bank.ts` 的 `ONSET_FRACTION`，想让手感更贴身就把它调大。
  配套的是 `sfx.ts` 里 1.2ms 的淡入：起播点在波形中间，不淡一下会"啪"一声。
- 不要烘进明显的室内混响，画面是户外战场。
- 单声道优先；采样率 44.1kHz 或 48kHz。
- 文件夹可以暂时为空，缺少某类素材时游戏会静默跳过，不会报错。

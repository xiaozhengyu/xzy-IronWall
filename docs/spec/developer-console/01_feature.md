# Feature: Developer Console

## Player Problem

开发和调试游戏时，当前 F1 菜单已经可以跳波次、切换技能和调整敌人数量，但获取指定技能、发放指定道具、锁定生命/蓝量等操作分散在代码或缺少入口，验证玩法需要反复等待随机状态出现。

## Desired Outcome

开发者在开发环境中打开 F1 调试面板，即可通过可视化控件快速准备测试场景，并在不修改存档、不改变正式玩法的前提下观察技能、道具和战斗配置。

## In Scope

- 将现有 F1 调试能力集中到独立的 Developer Console 视图。
- 直接装备/卸下指定技能；装备调试技能时自动设为满级。
- 选择任意道具并按指定数量立即发放到快捷栏。
- 分别锁定当前生命值和当前蓝量；关闭后恢复正常规则。
- 提供补满生命、补满蓝量和无敌开关。
- 收纳现有跳波次、敌人数、自动攻击、倒下重开、天气和清场操作。
- 仅在开发环境可见，生产构建移除 F1 入口、Developer Console UI 和 DebugBridge；Battle 中已有调试 API 保持不可达，以兼容现有调试架构。

## Out of Scope

- 文本命令解析器或控制台命令语言。
- 调试配置持久化、分享或导入导出。
- 发布版调试入口。
- 通用的地图、敌人属性和掉落概率编辑器。

## Acceptance Criteria

- [ ] F1 打开的开发面板可以展示并操作技能、道具、资源锁定和战斗控制四组能力。
- [ ] 指定技能可以立即装备/卸下，装备后按现有调试规则为满级。
- [ ] 指定道具和数量可以立即进入快捷栏；快捷栏满时保留现有容量规则并给出可见反馈。
- [ ] HP/MP 锁定可以独立开关，开启后每帧保持开启瞬间的数值，关闭后伤害、消耗和回复恢复正常。
- [ ] 新开一局会清除锁定、无敌和其他临时调试状态。
- [ ] `npm run build` 通过，且生产构建不包含 F1 调试入口、Developer Console UI 或 DebugBridge。

## Constraints

- UI 只负责展示和发起调试动作，战斗状态仍由 `Battle` 持有。
- 复用现有技能、道具、波次和战斗调试接口，避免第二套规则。
- 保持当前未提交的聚灵符功能改动，不覆盖或重置用户工作区内容。
